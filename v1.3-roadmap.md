#### Core Classes

| Class | File | Purpose |
|-------|------|---------|
| `SwarmKernel` | `swarm-kernel.ts` | Top-level orchestrator. Decomposes missions → delegations, manages agent lifecycle |
| `AgentRegistry` | `agent-registry.ts` | Register/unregister agents, query by role/capability |

#### The Swarm Loop

```
1. SWARM_RECEIVE: SwarmKernel receives mission from EventLoop
2. DECOMPOSE: Break mission into sub-tasks (deterministic splitter)
3. ASSIGN: DelegationManager assigns to agents by role/capability
4. EXECUTE: Each agent runs its own EventLoop (Perceive→Plan→Execute→Reflect→Memorize)
5. REPORT: Agents report results back through EventChannel
6. CONSOLIDATE: SwarmKernel merges results into final outcome
7. REFLECT: Reflection on the swarm-level outcome
```

#### Governance Integration

Every agent action goes through `GovernanceGateway.intercept()`:
- Agent messages with `requiresGovernance: true` are intercepted
- `ActionIntent` is constructed from the message payload
- Agent trust level affects policy evaluation (restricted agents have fewer permissions)
- All inter-agent communication is audit-logged

#### CostGuard Integration

- `CostGuard` tracks per-agent spend (always $0)
- Agent delegation requests are checked against cost limits
- Swarm-level cost dashboard shows per-agent utilization

```typescript
// Consolidated behavioral rule
interface BehavioralRule {
  id: string;
  rule: string;                    // "Always verify file exists before reading"
  category: RuleCategory;          // 'safety' | 'efficiency' | 'accuracy' | 'preference'
  confidence: number;              // 0-1, increases with reinforcement
  evidenceCount: number;           // how many episodes support this rule
  contradictedCount: number;       // how many episodes contradict
  sourceEpisodeIds: string[];      // which episodes generated this rule
  createdAt: string;
  lastReinforcedAt: string;
  status: 'active' | 'weak' | 'deprecated';
  ttlMs: number;                   // time-to-live
  relevanceScore: number;          // 0-1, decays over time
}

type RuleCategory = 'safety' | 'efficiency' | 'accuracy' | 'preference';

// Raw episode for compression
interface RawEpisode {
  id: string;
  missionId: string;
  goal: string;
  actions: EpisodeAction[];
  outcome: 'success' | 'failure';
  duration: number;
  timestamp: string;
}

interface EpisodeAction {
  module: string;
  operation: string;
  target: string;
  result: 'allowed' | 'blocked' | 'approval_required';
  governanceDecision: string;
}

// Consolidation result
interface ConsolidationResult {
  id: string;
  episodesProcessed: number;
  rulesGenerated: BehavioralRule[];
  rulesReinforced: BehavioralRule[];
  rulesDeprecated: BehavioralRule[];
  rulesMerged: BehavioralRule[];
  timestamp: string;
  duration: number;
}
```

### New Classes

| Class | File | Purpose |
|-------|------|---------|
| `MemoryConsolidationService` | `consolidation-service.ts` | Background orchestrator. Schedules and runs consolidation cycles |
| `EpisodeCompressor` | `episode-compressor.ts` | Compresses raw episodes into abstract patterns |
| `RuleExtractor` | `rule-extractor.ts` | Extracts behavioral rules from compressed episodes |
| `RuleValidator` | `rule-validator.ts` | Validates rules against evidence, handles contradictions |
| `RuleDecayManager` | `rule-decay.ts` | Manages TTL, relevance decay, pruning |

### Consolidation Pipeline

```
1. COLLECT: Gather episodes from last consolidation cycle
2. COMPRESS: EpisodeCompressor groups similar episodes, extracts patterns
3. EXTRACT: RuleExtractor generates candidate rules from patterns
4. VALIDATE: RuleValidator checks against existing rules + evidence
5. MERGE: Combine overlapping rules, reinforce validated ones
6. DECAY: RuleDecayManager reduces relevance of old/unreinforced rules
7. PRUNE: Remove deprecated/expired rules
8. INDEX: Store final rules in SemanticVectorMemory for retrieval
```

### Integration Points

- **ReflectionEngine**: After `reflect()`, raw episodes are queued for consolidation
- **SemanticVectorMemory**: Rules are stored as vector documents for semantic search
- **WorkingMemory**: Active rules are loaded into working memory for real-time access
- **GovernanceGateway**: Safety rules are promoted to policy suggestions

#### Code Validation Rules

Before execution, code is validated:
1. **No `child_process`** — block shell access
2. **No `eval()`** — block dynamic code injection
3. **No `fetch`/`http`** — block network access (unless allowed)
4. **No `fs` writes** — block filesystem modification (unless sandboxed)
5. **No infinite loops** — detect `while(true)` without breaks
6. **No prototype pollution** — block `__proto__` manipulation

#### Governance Integration

Every code execution goes through `GovernanceGateway.intercept()`:
```typescript
const intent = {
  id: generateId(),
  module: 'exec',
  operation: 'execute',
  target: `sandbox:${language}:${codeHash}`,
  payload: { code, language, sandboxConfig },
};
const gate = governance.intercept(intent);
```
